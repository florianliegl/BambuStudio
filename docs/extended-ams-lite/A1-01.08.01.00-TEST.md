# A1 firmware 01.08.01.00: one-slot replacement test

The user reported A1 firmware **01.08.01.00**, an idle printer, and four AMS Lite
slots loaded with different PLA colors, and a **0.2 mm nozzle installed**. No printer-control connector is available
in this task. Software checks run locally; the user performs and observes the
physical print. No print job, heating command or motion command has been sent.

## What this test establishes

The coupon uses two virtual filaments mapped to **physical slots 1 and 2**.
It prints a 12 x 8 x 0.9 mm rectangle in three 0.3 mm bands:

1. Bottom: original spool in slot 1.
2. Middle: unchanged spool in slot 2, using a normal A1 filament change.
3. Top: a replacement spool in slot 1, using a normal A1 filament change.

There is one native pause at the start of layer 7, Z=0.7 mm. At this point slot 2
is loaded in the nozzle and slot 1 should already have been unloaded by the
normal preceding change. Only slot 1 is replaced during the pause. No active-slot
unload command, firmware remapping command or end-of-print unload macro is
inserted into the middle of the print.

The project is generated from the bundled **Bambu Lab A1 0.2 nozzle**, **0.10mm
Standard @BBL A1 0.2 nozzle**, and **Generic PLA @BBL A1 0.2 nozzle** system presets. Its initial build
plate setting is Textured PEI; select the actual installed plate before slicing.
The preset's ordinary purge and prime-tower handling is retained. The project
contains editable geometry, settings and a native pause, without embedded G-code.

## Run the attended test

1. Open **A1 AMS Lite one-swap test.3mf** as a project in the **official signed Bambu Studio**.
   Its desktop shortcut can open it directly. Keep the printer at A1 0.2 mm;
   select the actual build plate and the appropriate PLA profiles.
2. Slice normally. Do not apply Extended AMS Lite optimization to this probe.
   Confirm nine layers and a pause marker on layer 7 before printing.
3. Sign in to the official Studio and select your printer if it is not connected.
   In the Send dialog, explicitly map **filament 1 to physical AMS Lite slot 1**
   and **filament 2 to physical slot 2**, regardless of the example preview colors.
   Slots 3 and 4 are unused by the test. Keep the AMS enabled.
4. Start the print and remain beside the printer. It should print the bottom in
   slot 1's original color, change normally to slot 2, and print the middle.
5. At the pause, confirm that slot 2 remains loaded and slot 1 has already
   retracted normally. Replace **only the inactive spool in slot 1** with another
   PLA color using the normal AMS Lite feeder release and staging procedure.
   Leave slot 2 and the toolhead alone. A spare PLA spool is preferred; an unused
   spool from slot 3 or 4 can supply the replacement if removed normally.
6. If slot 1 is still engaged in the toolhead, filament resists withdrawal, or the
   AMS refuses normal staging, leave the job paused and report that result. Do
   not force filament, operate the cutter manually, disconnect tubes, or send
   experimental unload commands to finish the test.
7. Once the replacement is normally staged in slot 1, resume with the printer's
   normal Resume control. Observe its normal change from slot 2 back to slot 1,
   purge, and extrusion of the top band in the replacement color.

Report: whether slot 1 was free at the pause, whether the replacement staged,
whether resume loaded the correct slot and purged, whether the top band printed
in the replacement color, and any printer message or error code.

## Verification and limits

The dedicated integration test loads the real bundled presets, performs normal
slicing/export, verifies the pause at layer 7 while filament 2 is selected,
checks subsequent extrusion from filament 1 and a following native T0 command,
saves the project, reloads it and reslices it to verify the pause survives.
These assertions validate the project's software structure; they do not emulate
the A1 firmware or prove a successful spool change.

Local verification: **115 assertions across four integration test cases pass**.
The project generation run adds one output-file check (30 assertions in the
hardware-probe case). The desktop project has no embedded G-code.

The custom build's network plugin loads, but the user received Bambu's
`unsigned_studio` restriction when using printer functions. Plugin compatibility
does not establish print authorization. The installed official Studio is the
same version, 02.08.02.61, with a valid Authenticode signature. The test shortcut
now opens that executable with the ordinary project and its native pause.
No custom Extended AMS Lite feature is required for this one-slot test.

A successful physical test would establish inactive-slot reuse for this tested
case. It would not certify active-slot replacement, an all-four-at-once batch,
within-layer pause placement, changed RFID behavior, mixed materials, reconnect
or cancellation behavior.

An implementation option to investigate after this test is a **two-stage visit**:
replace inactive slots, let a normal tool change unload the remaining active
slot, then pause again so that last spool can be replaced while the user is still
present. That would use more than one firmware pause per human visit. It is not
implemented or hardware-validated by this probe.

## Firmware evidence

The official [A1 firmware download notes](https://bambulab.cn/zh-cn/support/firmware-download/a1)
for 01.08.01.00 describe a fix to external-spool feed/retract behavior while paused.
They do not establish the same operation for an occupied AMS Lite slot.
The official [A1 Combo quick start](https://cdn1.bambulab.com/documentation/quick-start-f507128172bdf/Quick%20start%20guide%20-%20A1%20combo-EN.pdf)
describes ordinary AMS Lite spool loading and its feeder release button. The
test uses the existing A1 tool-change and pause macros from this repository.

## Reproduce the project generation

Build the `extended_ams_lite_integration` target. With the dependency `bin` and
`bin/occt` directories in PATH, set `EXTENDED_AMS_PROBE_OUTPUT` to a dedicated output
directory and run the test filter `[HardwareProbe]`. The generator refuses to
overwrite an existing test project. Without that environment variable, all files
are temporary and no desktop output is produced.
